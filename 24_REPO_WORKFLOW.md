# 24 — Repository Workflow

## Branching

Use short-lived feature branches or the repository's existing branching convention. Keep commits focused on one system or content group.

## Commit guidance

Good commit:

`Add beer equipment swap state and tests`

Bad commit:

`Update stuff`

## Pull requests

Each PR should state:

- what changed;
- which game rule it implements;
- what tests were run;
- whether save data changed;
- whether content/docs changed;
- known limitations.

## AI-generated changes

AI agents should make changes in small reviewable batches. Large autogenerated rewrites are discouraged because they make regressions harder to find.

## Documentation synchronization

Gameplay rule changes require the relevant `docs/*.md` file to be updated in the same change.

## Assets

Keep source asset names stable. Avoid replacing assets with temporary files whose naming will confuse content references.

## Pre-merge checks

- build;
- tests;
- content validation;
- no broken internal docs links;
- no accidental generated junk files;
- no committed secrets;
- browser smoke test for major gameplay changes.
